> 審核日期：2026-08-16

## 結論

本輪確認 R13 的既有核心修正均已生效，TypeScript 型別檢查與完整模組驗證皆通過；目前仍有兩項程序／結構缺口需要修正：一項會讓玩家輸入造成戰鬥選單拋錯，另一項會讓非法地圖資料通過驗證並進入渲染程序。

## P1：武器組技能配置缺少實際 Workflow

### 現況

- `src/app/composition/router.ts` 將 `configureWeaponSet` 直接路由到 Inventory handler。
- `src/modules/inventory/system.ts` 只驗證物品、持有人、裝備位置與手部合法性，之後原樣保存 `selectedSkillIds`。
- 架構文件寫明「選擇的技能已由 Workflow 驗證」，但 `src/app/workflows/` 目前只有旅行事件 Workflow，沒有武器組配置 Workflow。
- `src/modules/combat/queries.ts` 的 `getAvailableActions()` 會對武器組中的技能 ID 直接呼叫 `getSkillView()`，沒有先確認 Definition 存在或角色已學會。

### 影響

- 不存在、已移除或未載入的技能 ID 可以進入武器組。
- 戰鬥選單查詢可能直接拋錯，而不是把非法配置視為不可用。
- 尚未學會的技能，以及不符合 `activationHand`／`weaponRequirementIds` 的技能，目前仍可能被保存。
- `handleUseCombatSkill()` 雖然會擋未學技能，但無法防止戰鬥選單在更早的 Query 階段崩潰。

### 建議修正

1. 新增武器組配置 Workflow，依序查詢：
   - 技能 Definition 是否存在。
   - 角色是否已學會技能。
   - 技能的啟動手與武器需求是否符合新武器組。
2. 驗證全部通過後，才送出 Inventory 的 Internal Command。
3. `getAvailableActions()` 仍應採防禦性讀取；遇到失效的存檔引用或內容包缺失時跳過該技能，不得讓整個 Query 拋錯。
4. 加入至少下列整合測試：
   - 不存在技能 ID 被拒絕，Loadout 不改變。
   - 未學技能被拒絕。
   - 武器需求不符被拒絕。
   - 舊存檔含失效技能引用時，戰鬥選單仍可建立。

## P1：雲華內容建置繞過共用地圖驗證器

### 現況

- `build_yunhua_content_html.mjs` 仍維護一份本地 `validateMapLayouts()`。
- 這份驗證器只檢查部分 ID、格位、特殊房間大小、連線端點與出口數量。
- 它沒有檢查共用驗證器已實作的樓層連通、紅門守護與跨層樓梯鏈。
- `docs/03_content/yunhua/yunhua_content.data.mjs` 的 `adventureValidationSummary` 目前只呼叫 `validateAdventureStructure()`，同樣沒有呼叫共用 `validateMapLayouts()`。

### 影響

雲華內容即使違反正式地圖規則，資料摘要與 HTML 建置仍能成功。本輪把目前雲華資料交給共用驗證器時，實際得到 7 筆錯誤，詳見《遊戲資料內容的審查結果》。

### 建議修正

1. 移除雲華 builder 內的重複地圖驗證器。
2. 讓四國資料都從 `docs/03_content/shared/map_model.mjs` 使用同一個 `validateMapLayouts()`。
3. 將地圖驗證結果納入各文化唯一的 `validationSummary`／`adventureValidationSummary`。
4. Builder 只消費驗證結果；驗證失敗時停止產生 HTML，避免錯誤資料被寫成看似正式的產物。

## P1：雲華仍保留獨立且過期的地圖 Renderer

### 現況

- 維爾敦、奧雷連與薩菲爾已使用 `docs/03_content/shared/map_render.mjs`。
- 雲華仍在 `build_yunhua_content_html.mjs` 內維護另一份 `renderMapFloor()`。
- 雲華版本仍用 `room.stair === 'up'` 判斷樓梯，但正式資料使用的是 `↑`／`↓`。

### 影響

- 四國並未真正共用唯一地圖渲染程序。
- 共用 Renderer 修正後，雲華不會自動獲得修正。
- 目前雲華所有上樓梯都被畫成向下樓梯。

### 建議修正

移除雲華的地圖模型、圖例、樣式與 Renderer 複本，改為直接 import 共用 `map_model.mjs` 與 `map_render.mjs`。四國 Builder 僅保留文化頁面組裝差異。

## P2：共用地圖驗證器尚未封閉欄位值域

### 已驗證缺口

目前 `validateMapLayouts()` 不會拒絕：

- `room.anchor` 不屬於該房間的 `cells`。
- `room.marks` 含有未知值，例如 `unknown-mark`。
- `connection.type` 含有 `open`／`door` 以外的值，例如 `portal`。

以同時包含上述三個錯誤的測試地圖呼叫驗證器，結果仍為零筆錯誤。

### 影響

- 非法 anchor 會把符號畫到錯誤格位或圖外。
- 未知 mark 會讓 Renderer 讀取不存在的標記定義，可能直接拋錯。
- 未知連線種類會被 Renderer 當成有缺口但不是紅門的通道，造成資料語意被靜默改寫。

### 建議修正

在共用模型層定義並驗證封閉值域：

- `MapMark = treasure | event | large | trap | resource`
- `MapConnectionType = open | door`
- `anchor` 必須屬於同一房間的 `cells`

並為三種非法輸入各加入一個驗證器測試。

## 已確認修正有效

- 裝備變更事件改為比對完整 Loadout，跨武器組與多格裝備不再漏發事件。
- 過期地圖刷新鎖不再阻擋新的委託鎖。
- 地圖出口數量已允許 1～3 個。
- 房間重複 ID、重疊格、非連續形狀與樓層斷線已有共用檢查。
- 共用 Renderer 原始碼已能直接顯示 `↑`／`↓`；但目前 HTML 產物尚未全部重新生成。
