# 目前實作狀態

本文件是唯一的實作狀態與未完成項目來源。先核對程式與驗證，再更新此頁；完成的待辦直接移除。歷史留在 Git，不在工作樹保留舊交接或審查副本。

## 正式可用範圍

- 開局／繼續旅程、16:9 橫向場景舞台、固定視角 3D 城鎮模型互動與右側設施頁簽、日期／所在地、繁中／英文、操作回饋、旅程紀錄與死亡結束畫面。Electron 與瀏覽器共用介面，桌面支援 800px 以上視窗，舞台等比例縮放並留黑邊；設施及人物視窗內部捲動。模型建築的滑鼠選取與頁簽的滑鼠／鍵盤選取會同步顯示建築抬升、投影與柔和呼吸光暈及名稱，兩邊皆可直接進入設施。探索按實際房間形狀、相鄰門與樓梯操作，戰鬥呈現左右站位及下方指令列。
- 雲華主循環：購買武器與防具／出售背包物品 → 裝備與配招 → 接鎮壓／討伐委託 → 探索地圖與樓梯 → 回合戰鬥 → 出口競價或直售戰利品 → 回原公會領錢與熟練度 → 休息／訓練再出發。
- 城市旅行使用城門口的 3D 大地圖；家園、訓練與酒館招募保留既有正式入口；未開放的設施不顯示可操作按鈕。
- 傷害技能與反擊的倍率已轉成 combat-effect／combat-damage-rule，武器副屬加入傷害，防具按比例減傷；生命／魔力上限包含角色主屬。裝備係數只縮放一次。
- 委託結案、貨幣分配與成長在交易內完成，重複領獎拒絕且不變更存檔。只有完整接線的鎮壓／討伐會在正式開局與刷新生成，接取及結束期限都有排程。
- 實際內容包以 `content/manifest.json` 為準。目前載入 core、雲華與 world-cities；後者提供其他十二城的城市、路線、文化名稱與住宿。各國完整商品、委託與冒險內容仍未開放。
- 玩家命令由 GameSession 與交易執行器處理，ID 與 RNG 可重播。世界結算使用核心排程排序、完成同日工作，且不倒退日期。
- 新遊戲建立地圖與商店週期工作。地圖刷新間隔與偏移來自 map-template v2；鎖定／有人探索時保留固定日曆及必要的次日重試。
- 戰鬥阻塞原因回傳 UI；未接線 port 產生明確 typed rejection，不把例外偽裝成成功。
- 每次接受玩家操作後自動儲存，另有手動儲存、匯出／匯入 JSON 存檔。重開恢復全部狀態，包含排程、RNG 游標、迷宮、裝備與戰鬥。

行囊的隊形配置使用正式命令儲存 3×3 站位，可交換隊員格位，重開及開戰沿用配置；戰鬥中由引擎拒絕更改。委託狀態彙整各城已接委託，接取與領獎仍在公會；道具分頁顯示背包，使用道具與學習書籍尚未開放。

## 城鎮 3D 場景

玩家介面使用[繪製圖集與木框面板](../app/assets/ui/README.md)。右側無底板及標題，放大的設施頁簽使用粗體描邊文字，採青綠織錦與舊銅雲紋獨立貼圖並包含類別圖示；Hover／鍵盤選取放大該項，緊鄰項目縮小並讓位，與模型光暈同步。底部僅保留行囊選單，內含裝備、隊形配置、委託狀態與道具四個分頁；商店商品、公會委託、訓練、家園、旅行及裝備選項均使用類別美術；設施視窗採固定木框與內部捲動區。右側與底部完整容納所有標籤；介面不顯示捲動條，長內容仍可用滾輪與鍵盤捲動。左上文化資訊牌包含城池圖示、所在地與世界日；依城市所屬文化選取青玉雲紋、木雕鐵飾、石紋金飾或藍釉銅飾，四國文化資訊牌隨正式所在地切換，語言選項收進右下進度管理。圖示尚非逐物品獨立美術，人物徽章不代表實際 NPC 外貌。

正式遊戲使用 `app/TownModel.tsx` 載入 Blender GLB，模型點擊與右側頁簽均連接既有設施操作，名稱及可操作性來自目前城市的 GameView。雲京十處功能建築分散於 36 棟不可互動住宅／倉房之間；重簷、特色屋瓦、煙囪、棚架與牌樓建立視覺層級。射線只接受最前方可見模型，街坊不會穿透點到後面的設施。

城鎮包含四面城牆、角樓、水道、市集與三座橋；正式城內使用固定角度的街區近景，預設以中央街坊為主、大部分城牆在畫面外，按住滑鼠左鍵或右鍵只做上下左右平移，沒有旋轉與縮放。模型 Hover 稍微追焦，頁簽／鍵盤選取會帶向對應設施；拖曳優先並抑制誤觸進入設施。大地圖中的城池預覽仍維持全城視野。即時陰影、模型浮起及呼吸光暈已接入正式介面。減少動態效果偏好停用浮起、光暈脈動與平移補間。載入或 WebGL 失敗會顯示錯誤與重試，仍可用設施頁簽操作；離開城鎮時釋放動畫與 GPU 資源。

城鎮作者工具在配置住宅與樹木時檢查獨立建築、文化地標及景物的幾何交叉；階台建築按完整占地決定高度並補基座。大地圖減面保留地基、階台、路面與城垣的結構輪廓，城市完整占地周圍預留平地，外部道路、水道與樹木避開城池。輸出後以 Blender 再檢查十六城及大地圖的城市／環境交叉，驗證結果綁定受檢模型雜湊，避免修改模型後沿用舊結果。

[場景美術](../app/assets/README.md) 記載可編輯 `.blend` 與重建入口。標題使用雲京渲染圖，設施視窗使用所在城市的渲染圖；舊 2D 城鎮圖及輪廓遮罩已移除。十六城各有獨立模型：雲京水道、青岑階台、澄浦港埠、赤嶺窯城、霜灣雪港、杉脊林堡、晨冠教堂城、灰楯石堡、星井綠洲、赤帆驛站（弧面藍釉穹頂、雕拱窗、陽台、側面拱窗、露台、錯縫砌石城牆、分層塔樓、木條門板／銅環／鉚釘、UV 刺繡帆布與獨立地坪／藍釉貼圖及烘焙法線）、冰鑿採石城、燼鐵鍛爐城、風穗風車城、白崖港、鹽鏡階池城與赭階峽谷城；十六城旅行後皆切換對應模型，新增十二城可住宿並繼續旅行。赤帆驛採中央水池廣場、西側紅帆市集、北側公共建築、西南工坊與東南十六棟住宅的固定街區布局；主路、橫街與住宅巷道分級配置，世界縮景同步使用同一布局。尚無人物、環境及轉乘船隻動畫。

城門口進入 [3D 四國輿圖](../app/assets/geography/README.md)，預設聚焦玩家周圍城市，可巡覽、旋轉、縮放並切換全圖總覽，選取城市並開啟模型預覽。大地圖是一片連續大陸，雲華與薩菲爾之間形成四周被陸地包圍的雲星大湖，使用適量網格呈現雪峰、丘陵、分支山脊、台地與峽谷的幾何高低差；道路依網格表面取樣貼地，搭配 UV 地表／岩層色彩貼圖、烘焙法線、材質粗糙度、各向異性取樣及陰影；城市縮景保留整城城牆、街坊與地標的減面版本，主堡比小城大。包含河流、森林、雪地、沙地與曲線道路；城市位置和道路折點是美術作者資料，東西南北文化方位沿用正式設計。所有城際連線均對應正式路線：國內道路加上青岑—燼鐵、白崖—霜灣、風穗—鹽鏡、澄浦—赤帆跨國陸路，以及雲京—星井渡湖線。地圖提供「可直達」入口；非相鄰城市需轉行。湖面虛線只畫水上航段，沿岸接回道路；旅行使用正式 3／6／9 日模式。預覽不改變存檔，旅行選項仍由正式 GameView 決定。

## 開局與平衡

`content-source/player-scenario.ts` 是開局設定，預設從雲京、25 歲、5,000 旅費開始；單手武器／中甲 Lv.5、投擲 Lv.3。仍需自行購買裝備並配招。Tier I 怪群為三隻；初期可從舊漕渠與沉倉開始，打一場後找出口返城。這是目前作者層的可調首版平衡，並非宣稱四國 GDD 全部完成。

### 開局委託單一的原因

開局會立即生成地圖內容與商店商品，並非等待玩家行動才建立世界。`content-source/yunhua/maps.ts` 目前只有三張地圖配置怪群／Boss 預算；寶箱、地圖事件、綁架與控制內容沒有生成預算，其餘六張地圖也没有遭遇預算。商店有商品，不等於有可運送的任務貨物。

正式 bootstrap 與 `context-assembler.ts` 另外以 `enabledKinds` 限制只生成鎮壓／討伐，因為其他委託的貨物保留／交接、暫時角色與完成流程尚未接通。`verify:ui` 比較開局與連續 35 日正常行動的內容來源；時間推進會刷新現有內容，但不會新增未配置的來源或解鎖委託種類。

**目前不啟用開局預先模擬。** 優先補齊事件／物品來源與運送／救援完整流程，再接 NPC 行動對世界的影響。之後可把預熱天數放在作者層，以正式排程從入場日前數個刷新週期推進，最後才建立玩家；保留同一 RNG 與世界日期規則，不消耗玩家年齡、旅費或物資，也不能把已過期委託當成開場內容。未完成這些接線前，只把日期往前跑 N 天無法解決本問題。

## 存檔行為

單一本機槽位及上一份備份，儲存在瀏覽器 Storage；Electron 的網站儲存由自己的 userData 管理。桌面、開發網站與不同網站 origin 不共用槽位。清除網站資料會移除存檔。

讀取前檢查 checksum、存檔版本、Content Manifest Identity、由型別產生的 JSON Schema、核心時鐘／序號、玩家隊伍與排程。損壞或不相容的存檔拒絕載入，畫面提供備份還原或重新開局；不靜默重置。寫入失敗顯示錯誤並保留既有主存檔，已成功的遊戲動作不回滾。checksum 用來偵測損壞，不是防修改簽章。

目前只接受相同內容身分與存檔格式。新增十二城與跨國路線已改變內容身分，舊內容包的存檔需保留或匯出，使用新世界需另開新旅程。未提供跨內容版本 migration、跨裝置同步或 Steam Cloud。

## 驗收入口

- `npm run verify`：工作樹的引擎／UI 型別、紀律、模組測試、UI 門面整合、存檔 schema、內容包與四國 HTML 同步、範圍、文件連結及正式 UI 建置。
- `npm run verify:ui`：真實 bundle 開局、連續 35 日正常行動、28 日訓練、週期刷新、儲存／還原、後續動作的決定性、備份及儲存失敗保護。
- `npm run verify:playthrough`：正式內容的購物／裝備／配招、探索樓梯、戰勝、真實掉落物競價與直售、委託報酬及成長、重複結案拒絕、戰鬥存檔重播。
- `npm run verify:desktop`：隔離 Electron profile 驗證開局、正式 GLB 載入、所有可用地標的模型射線選取與頁簽雙向 hover、移出清除、鍵盤高亮、3D 建築點擊，以及公會／商店／人物頁操作、購物／裝備／配招、繼續遊戲、地圖移動、探索中開關人物視窗、戰鬥勝利及 16:9 舞台完整縮放；截圖輸出在忽略追蹤的 `dist/`。不碰玩家存檔。
- `npm run verify:geography`：十六座模型各自不同、十種設施根節點、街坊、世界地標與全部正式城際連線；另檢查地表是一片連通陸地、只有外海岸與內陸湖岸兩個閉合邊界；幾何交叉檢查結果必須無錯誤，且 SHA-256 與目前十六城及大地圖的 `.blend`／`.glb` 完全一致。
- `npm run verify:world-travel`：正式內容逐城旅行、住宿、日曆推進、抵達存檔重載與回到雲京。
- `npm run verify:atlas`：隔離存檔實際查看十六城、確認預覽不改動狀態，旅行至全部十六城，驗證跨國陸路、渡湖線、抵達存檔及雲華地標射線。
- `npm run report:content`：目前實際載入資料與缺少的 resolver binding；不是完成率。
- `npm run verify:gap`：文字掃描供查找線索；會命中否定句和設計說明，不能直接當作未完成清單。

## 文件與資料維護

- `docs/00_core/architecture/` 是目標契約；是否已接線只看本頁與正式流程測試。
- `content-source/` 是 runtime 作者層，修改後執行 `npm run content:packs`。
- 四國閱讀版由 `npm run content:all` 產生，不手改 HTML。
- map-template v1 沒有刷新週期欄位。作者資料須依該國設計明確升為 v2；不在 runtime 猜測週期。舊版存檔在內容身分不符時拒絕載入。
- 修改存檔結構後執行 `npm run schema:save` 並檢查存檔相容策略；不可只改 JSON 產物。
